# Veilward — Phase 9 / R40 native physical shoreline recovery

**Base:** R39c `d4c502c`. **Status:** Implementation, not creator art approval. Phase 9 active, Phase 10 locked.

## Root cause found in actual gameplay screenshot
The Falls river looked like a straight cyan diagonal because R35d clipped its correct physical 180-unit river polygon and filled all the way to its dry-bank boundary in a sharply contrasting blue-green material. The R39 native dry-bank rocks correctly lay on land, but they could not fix a hard paint join beneath them. Widening the water *collision* or shifting shore points would have made the art lie about traversal.

## R40: actual rendering changes
- New `terrain_art.fallsShoreBands(bounds)` builds both original river banks from the R35d Frostbridge centerline, sharing the same vertex normals. At each source section the cross-bank paint spans **114–286 world units** from the channel centerline, feathered around the unchanged physical **180-unit water limit**. Paint fades from transparent blue-green water through desaturated wet moss and back to transparent original dry woodland; no cyan/white outline, square checkerboard or arbitrary parallel waterway.
- The blend is painted after the original source forest floor and before physical paths/decks, so the route remains legible and the forest-and-water contact is integrated in the real streamed world. Sections are culled in world-space, never tile-local. No new static textures, no image generation, and no added collision.
- A few subtle, short, flow-aligned current accents may appear only on the water side; there are no apparent stepping stones or alternate walks.
- The original R39 dry riverbank rock treatment now attaches restrained, un-stretched R18 painted fern clusters on the verified landward side of selected real bank rocks. Source geom, forest roots, crossings and water are unchanged.
- All PWA cache URLs for `terrain_art.js` and `world_greenwood_art.js` and the service-worker version rotate, so the iPhone Home Screen loads this pass as one consistent unit.

## Follow-up: channel-edge stream culling (2026-11-08)

The native R40 shoreline pigment extends to **286 world units** from the original river centerline (180 physical water + 106 dry-bank feather), but the broad channel bounding box was padded by only **205**. On streamed edge tiles this could omit the outer shoreline fade while adjacent tiles still painted it, leaving a visible transition seam. `terrain_art.js` now uses a conservative 300-unit channel bound for its initial cull. The original river centerline, 180-unit physical hazard, crossings, roads, save keys, pigments and actual shoreline panel geometry are unchanged. This is a targeted render-culling fix, not an art-approval claim. GitHub commit `69a67240526b0dc4ffd0a9b114eef9acd3224d9d`. ## R40b — native river-mask / feather alignment (2026-11-08)
The R35d water polygon computes a centered tangent normal at **every** source vertex. The R40 shore wash had an exceptional previous-segment normal at sharp bends; at those points its inside/outside feather could diverge from the actual visible water mask, exposing triangular hard joins even with R40's broader culling. `terrain_art.js` now uses the identical R35d centered tangent for each original channel vertex. No channel points, radius, collision, crossings, route, forest roots, save keys, or source assets change. `tests/greenwood_falls_shoreline_r40.test.js` now compares every emitted wash vertex normal with the independently computed physical-mask normal to prevent this mismatch returning. This is a visual-seam correction, **not** proof the finished artwork meets the golden reference. Code commit `28db19a07413968a6f7bc23171f6b56e76a1aadf`; regression commit `9dca03695ad82d1878d420033f1f37c11df6eb06`. Check GitHub Actions and actual real-game screenshots for confirmation; creator acceptance stays 0%, Phase 9 remains active, Phase 10 locked.

## R40c — stable shoreline pigment at tight bends (2026-11-09)
The shoreline panel's four vertices still follow the authoritative R35d water-mask normals. Its **gradient axis** now uses the current physical centerline segment's unit perpendicular instead of averaging adjacent station normals: opposing normals at a hairpin could previously collapse the gradient to a point and create a hard wedge. This changes only the rendered cross-bank pigment and its subtle water-side streak positioning; physical channel, collision, crossings, original source vertices, paths, quests and saves remain untouched. A regression assertion requires each actual native canvas gradient to span the full **172-unit** feather. The HTML/service-worker terrain URL and worker cache key were rotated together. Commits: `d064ead8` (painter), `25844cd` (regression), `8a2471c` (HTML), `87f193f` (worker). The correction needs real screenshot review and confirmed CI/Pages status; it is **not** creator art approval. Phase 9 remains active at 0% creator acceptance; Phase 10 stays locked.


## R40g — actual quadratic water-brush crossing clearance (2026-11-09)
R40e's current-stroke guard sampled its start, midpoint, control handle and end. The control handle is **not on the quadratic curve**, so a bent stroke could still pass through a narrow physical bridge approach between those checks. The actual `terrain_art.js` painter now samples five positions **on the rendered quadratic Bezier** (t=0, .25, .5, .75, 1) using the same start/control/end coordinates as Canvas. If any sampled position lies within the authoritative 65-unit crossing clearance, that decorative stroke is omitted. This is a narrow visual-rendering correction: no physical river/road geometry, traversal, collision, quests or save keys change. The R40 regression assertions now require curve-based sampling rather than the obsolete control-handle check. Code commit `1a34e054d5c21f822427c7abe91cc4c5bbf0bf3c`; test commit `3e9ccd30e8789ff0ea6a6e317e163f7057806831`. CI, real-game capture, Pages status and physical iPhone inspection must be verified independently. Wider authored forest, cliffs and banks remain unfinished; creator visual acceptance is still 0%, Phase 9 active and Phase 10 locked.


## R40i — curved-bank pigment alignment (2026-11-09)

In the actual `terrain_art.js` shoreline painter, the R40h panel vertices follow interpolated source-vertex normals but the gradient axis and decorative current offset used the straight segment's perpendicular. On bends this makes the watercolor color stops drift across the intended wash footprint, risking harsh joins. R40i derives a normalized interpolated bank normal at each panel midpoint for the gradient and at each current-stroke station for the decorative offset/control point. Both banks still use the R35d authoritative source river and unchanged physical 180-unit water boundary; no road, bridge, collision, quest, save, or geometry edits. The HTML script query and offline service-worker cache were rotated to deliver the change.
